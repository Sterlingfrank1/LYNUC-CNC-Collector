# LYNUC RemoteComm 线路协议规格

本文是 `lib/client.js` 的实现依据。厂商未公开线路协议，以下内容来自对厂商客户端库的静态分析，**不是厂商文档**。

证据等级：

| 标记 | 含义 |
| --- | --- |
| **[L]** | 来自 Linux 库 `客户端库文件/LINUX/X86/libRemoteComm.so`（ELF32 i386）反汇编 |
| **[W]** | 来自 Windows 库 `客户端库文件/win32/release/RemoteComm.dll` 反汇编 |
| **[D]** | 来自厂商文档（`Protocol_doc/`、`客户端库文件/**/RemoteComm.h`、`globals.h`） |
| **[?]** | 推断，**尚未在真机验证**，见 [SITE_ACCEPTANCE.md](SITE_ACCEPTANCE.md) |

## 1. 为什么不用厂商 Linux 库

| 事实 | 证据 | 影响 |
| --- | --- | --- |
| 库是 32 位（ELF32 / EM_386），且只有 32 位 x86 与 ARM 版 | ELF 头；`LYNUC 远程通讯接口说明.md` | 64 位 Node-RED 进程无法 `dlopen`，FFI 路线不成立 |
| `remote_get_AbsolutCoordinate`、`remote_get_MachineCoordinate` 是空实现：`xor eax,eax; ret`（3 字节） | [L] `0xdfc0`、`0xdfb0` | 返回成功但不写任何数据，坐标永远拿不到 |
| 转速、进给、循环数、工件数、加工时间、相对坐标、行号等 API 在 Linux 库里不存在 | `.so` 导出表 | 业务数据大半缺失 |

上述 API 在 Windows 库里只是对公开宏变量的薄封装（见第 5 节）。协议是可以直接实现的 ASCII 文本，所以用 Node.js `net` 直连比桥接原生库更简单，也没有 32 位运行库、容器镜像和 ABI 的负担。

## 2. 连接

| 项 | 值 | 证据 |
| --- | --- | --- |
| 数据端口 | **TCP 4011** | [L] `newConnect` 中 `push 0xfab` |
| FTP 端口 | TCP 21，匿名登录（`USER anonymous` / `PASS `，期望 220/331/230） | [L] |
| 连接超时 | 1 s | [L] `timeval{1,0}` |
| 句柄上限 | 1000 | [L] `cmp edi,0x3e8`，仅客户端本地 |

厂商库在同一次 `remote_new_connect` 中同时建立两条连接。FTP 只用于文件传输，采集不需要。**[?]** 假定服务端不要求先完成 FTP 登录才响应 4011。

## 3. 帧格式

请求和响应都是 ASCII 文本，NUL 填充：

```text
请求: <4位命令码><参数>            补 0x00 到发送长度
响应: <4位命令码+1><内容>[(<回显>)]  最长为接收长度
```

- 厂商库每次调用 `send(固定长度)` 后只调一次 `recv(接收长度)` [L]。
- 响应命令码 = 请求命令码 + 1，不一致时厂商库返回错误 [L]。
- `内容` 是 C 字符串，从偏移 4 开始，到第一个 NUL 结束 [L]。
- 数值回复可带回显：`0008123.456(0007100)`。出现 `(...)` 时括号内必须等于原始请求，否则厂商库返回 -20；没有括号时直接解析 [L]。数值用 `strtod`，PLC 值用 `strtol(…,10)` [L]。

**[?]** 服务端是否把响应补满到接收长度未知，因此客户端同时兼容定长补零和不补零两种情况，并容忍响应被 TCP 拆包（见 `lib/client.js`）。

## 4. 心跳

厂商库后台线程每 50 ms 巡检一次；连接正常且空闲超过 50 ms 时发送 `0000`（128 字节）并收一帧响应（内容不解析）[L]。收发失败后约 1 s 重连 [L]。

本实现沿用 50 ms。服务端空闲断开阈值未知 **[?]**，与厂商行为一致是最安全的选择。

## 5. 命令表

本项目只实现下表读取命令。**写入类命令（0004、0027、0063、0114、0120、0021、0036 等）一律不实现**，采集器不具备修改机床状态的能力。

| 用途 | 请求 | 发送/接收长度 | 响应码 | 内容 | 证据 |
| --- | --- | --- | --- | --- | --- |
| 心跳 | `0000` | 128/128 | 不校验 | 忽略 | [L] |
| 读宏变量 | `0007<编号>` | 128/128 | 8 | 数值，可带回显 | [L][W] |
| 读宏变量（备用路径） | `0105<编号>` | 128/128 | 106 | 数值 | [W] |
| 读 PLC | `0060<地址>-<类型>` | 128/128 | 61 | 整数，可带回显 | [L][W] |
| 当前 NC 文件名 | `0081<通道>` | 1024/1024 | 82 | 字符串 | [L] |
| 打开文件路径 | `0030` | 256/1024 | 31 | 字符串（仅通道 1） | [L] |
| 当前文件总行数 | `0093<通道>` | 1024/1024 | 94 | 整数 | [L] |
| 主程序当前行 | `0123` | 128/128 | 124 | 整数 | [W] |
| 版本 | `0045` | 128/128 | 46 | 字符串 | [L] |
| 报警信息 | `0051` | 1024/1024 | 52 | 见下 | [L][D] |
| 序列号 | `0066` | 1024/1024 | 67 | 字符串 | [L] |
| MAC | `0069` | 1024/1024 | 70 | 字符串 | [L] |

PLC 类型：`1`=MO，`0`=MI [D]。地址不带 `MO`/`MOU` 前缀，须匹配 `^[0-9.]+.$` [L]，例如 `MO206.0` 写 `206.0`，`MOU205.20.24` 写 `205.20.24` [D 调用示例]。

报警串格式：`【1204】错误信息一_L2-【1011】错误信息二_L1`。`L` 为错误等级：1 致命、2 错误、3 警告、4 消息 [D #2101]。响应码不是 52 表示无错误 [L][D]。

未实现的读取路径：`0108`（实际进给，已用手册公开的 `#30037` 代替）、`0084`（SI 变量，业务不需要）。

未使用的批量读取：`0117<m1>|<m2>…` 与 `0102<起>-<止>` 可一次读 100 个宏变量 [W]，但其响应按 `数量×8` 字节接收，长浮点数有截断风险，且 Linux 库没有这条路径。首版用单点读取：3 轴配置下常规一轮 44 次往返，全量一轮 67 次，本机模拟器耗时约 8 ms；真机若确认延迟不够再评估。

字符编码 **[?]**：控制器运行 Linux，中文按 UTF-8 解码，非法时回退 GB18030。

## 6. Windows API 到宏变量的映射

这张表是 Linux 上能拿到完整业务数据的依据。

| Windows API | 实际行为 | 证据 |
| --- | --- | --- |
| `remote_get_AbsolutCoordinate` | 读 `#30118 + 50×轴序号` | [W] `0x75a6`，步长 `0x32` |
| `remote_get_RelativelyCoordinate` | 读 `#30119 + 50×轴序号` | [W] `0x75a7` |
| `remote_get_MachineCoordinate` | 读 `#30121 + 50×轴序号` | [W] `0x75a9` |
| `remote_get_AxisLoad(axis=1..9)` | `0105` 读 `#30082 + 50×axis`，即 `#30132`（X）起 | [W] `0x7582` |
| `remote_get_CyclesNumber` | `0105` 读 `#33503` | [W] `0x82df` |
| `remote_get_CurrentCyclesNumber` | `0007` 读 `#33504` | [W] `0x82e0` |
| `remote_get_S_CommandSpeed` | `0007` 读 `#33505` | [W] `0x82e1` |
| `remote_get_S_CurrentSpeed` | `0007` 读 `#33506`（手册未列） | [W] `0x82e2` |
| `remote_get_F_CommandSpeed` | `0007` 读 `#33563` | [W] `0x831b` |
| `remote_get_F_CurrentSpeed` | `0108` | [W] |
| `remote_get_WorkpieceNumber` | `0007` 读 `#33870` | [W] `0x844e` |

Windows 版这些 API 的 `channel` 参数实际未使用 [W]。宏程序手册写明第 2 通道变量在 PLC 中要 `+100000` [D]，远程协议下是否相同未知 **[?]**，默认按通道 1 采集。

## 7. 与历史方案的差异

历史方案（`legacy/`）假定端口 8080、二进制帧、`MO` 前缀地址，均与上述证据不符，详见 [legacy/README.md](../legacy/README.md)。
